# 标签整理判断规则

仅在分析真实标签截图或清单时读取。目标是把专栏方法转换成具体映射，不是复述文章。

这些规则是提出候选方案的判断依据，不是标准答案。标签名称和层级最终由用户的记忆习惯、使用场景与查找路径决定。若规则推断与用户解释冲突，以用户解释为准。

## 新手三阶段

主要依据《新手必看｜flomo 标签极简入门指南（必看）》：https://my.feishu.cn/wiki/ZsnSwdcoUi6130kD00Rc24RhnXd

- **0–50 条**：完全不用打标签，先养成无压力记录的习惯。可以用关键词搜索和每日回顾找回内容。
- **50–100 条**：花 15 分钟浏览已有笔记，从反复出现的真实主题、项目和兴趣中创建第一批标签。标签从记录中长出来，不凭空设计。
- **100 条以上**：用户感觉需要更稳定结构或行动入口时，再按需引入 PARA；不能只因数量超过 100 就强制重构。
- 标签格式为 `# + 标签名 + 空格`；层级标签格式为 `#一级/二级/三级`，最多三级，`/` 前后不留空格。
- 标签像便利贴，不是文件夹；一条笔记可以关联多个标签。
- 只给未来可能频繁调用的内容打标签，碎碎念和瞬间想法可以不打。
- 一条笔记通常选择当下最有帮助的 1–3 个标签，不追求覆盖所有可能分类。

## 一、标签问题识别

### 重复或近义

常见形态：

- `#写作`、`#写文章`、`#文字输出`
- `#AI`、`#人工智能`、`#ai工具`
- `#读书`、`#阅读`、`#书摘`

先询问或判断用途是否相同。相同才建议合并；一个表示长期主题、一个表示素材来源时可以分别进入不同层级，例如 `#领域/写作` 与 `#资源/书籍`。不要因为名称相近就直接判定重复。

### 颗粒度混用

同级同时出现宽泛主题和具体对象，如 `#知识管理`、`#flomo`、`#flomo标签`。优先改成层级：

```text
#领域/知识管理
#领域/知识管理/flomo
```

只有积累足够多、确实需要单独查看时才建立第三级。

### 类型混用

同级标签可能同时代表正在推进的事情、长期关注的方向、输入来源、情绪或场景、已过期内容。先分清用途，再决定是否放入 PARA，不要只按字面主题分类。

`工作`、`生活`、`个人成长`等是场景或主题，不天然等于 Area 领域。例如工作中可以同时存在 `#项目/客户交付`、`#领域/职业发展` 和 `#资源/工作模板`。用户习惯按场景查找时，可以保留 `#工作` 作为横向标签，与 PARA 标签同时使用；不要擅自把整个场景树搬进 `#领域`。

### 过期标签占据顶层

已经结束的年份、活动、产品或项目，优先改成 `#存档/年份/...` 或 `#存档/项目/...`。如果未来仍会频繁调用，可以保留原项目标签并说明原因。

## 二、多层级标签

flomo 格式：`#一级/二级/三级`。

- 一级：稳定的大类，数量应少。
- 二级：用户真实存在的主题、项目或资源类型。
- 三级：只有同一二级标签下已经积累较多内容、确实需要进一步筛选时才使用。
- 通常不超过三级；不要为每条笔记创造一个末级标签。
- `/` 前后不要空格，完整输入后再敲空格确认。

### 用户不会设置包含关系时

先解释“层级来自标签名称中的 `/`，不是另外创建文件夹”，再给两种操作：

1. 新建：在笔记中输入 `#一级/二级/三级`，完整输入后敲空格。
2. 修改已有标签：点击标签右侧 `...` → `编辑名称/图标`，把标签名改成完整路径，例如把 `知识管理` 改为 `领域/知识管理`。

修改完成后，侧栏会把相同前缀的标签显示为可以折叠展开的父子结构。示例必须优先取自用户截图中的真实标签，并提醒她先试改一个标签，确认显示效果符合预期，再批量调整。

## 三、PARA 判断

第一次向用户提到 PARA 时，先解释：它是一种按照“内容接下来怎么被使用”来整理信息的方法，不是要求用户学习的新术语。英文必须放在中文前面，让用户能把首字母与缩写直接对应：Project 项目、Area 领域、Resource 资源、Archive 存档。如果用户仍觉得抽象，再补充“正在做的事、长期关注的事、参考资料、已经结束的事”。

### Project 项目

有明确目标，正在持续推进，并且可以转化为具体行动。例如 `#项目/公众号改版`、`#项目/旅行计划`、`#项目/flomo专栏`。项目可以是短期的，也可以是公众号、社群、长期产品等需要持续运营的长期项目。

“短期内会不会结束”是常见判断线索，但不是唯一标准。优先确认：它是否有用户正在推进的明确目标，是否会持续产生下一步行动，以及用户是否把它视为一个具体事项。只有当它更像无限期维护的责任、标准或能力方向，而不是一个具体事项时，才更倾向 Area 领域。用户对自己项目的定义优先于框架的字面分类。“写作”“健康”“知识管理”等长期方向通常不是项目。

### Area 领域

长期承担、关注或精进的方向。例如 `#领域/知识管理`、`#领域/写作`、`#领域/健康`。领域不宜无限扩张，用户说不清是否会持续投入时，可以先保留原标签，不强判。

### Resource 资源

未来可能调用的信息输入来源或参考材料。例如 `#资源/书籍`、`#资源/播客`、`#资源/课程`。某本书内容很多时可用 `#资源/书籍/《书名》`；只有一两条摘录时不必新建三级。

### Archive 存档

已完成或暂不活跃但舍不得删的内容。例如 `#存档/2025`、`#存档/项目/旧课程`、`#存档/领域/心理学`。优先归档而不是删除，降低用户整理阻力。

### 说明 PARA 的好处

以荔枝的《标签分类：运用 PARA 法，建立从杂乱到清晰可用的笔记体系》为准：https://my.feishu.cn/wiki/G9BYwxDVlioOGIkouuLcVWxEndg

根据用户当下最在意的问题，选择 1–2 个价值说明，不要一次罗列全部：

- **聚焦精进领域**：帮助用户确定少数需要长期投入的方向，明确收集哪些知识，避免信息囤积和精力分散。
- **专注当前行动**：更容易识别需要立即推进的项目和需要定期回顾的领域，降低信息管理负担。
- **长期存储与回顾**：已结束或不活跃的信息移入存档，当下可以更聚焦，以后仍能找回和利用。
- **项目、领域和资源形成循环**：通过项目在行动中精进领域；项目遇到问题时，回到领域经验和资源笔记中找答案。这会让笔记支持思考和输出，逐步成为可复用的知识资产。

如果用户习惯从“正在做的事”查找，优先讲“专注当前行动”和“项目、领域、资源如何形成循环”；如果用户表达信息囤积或兴趣太散，优先讲“聚焦精进领域”；如果顶层充斥过期标签，优先讲“长期存储与回顾”。

### PARA 之外

PARA 服务于行动相关知识，不要求包办全部生活。梦境、感恩、人物观察、金句、情绪记录、私人纪念、随手碎片等标签可以独立存在。只有用户明确希望统一收拢时，再设计一个克制的个人一级标签。

## 四、迁移策略

1. 无论截图中有多少标签，先给一个可复用的用途判断标准，再选 2–3 个真实标签示范，不一次逐项给完。
2. 示范后请用户用相同标准判断 1 个相邻标签，并确认这一分法是否符合她的记录和查找习惯；助手负责补充和纠偏。
3. 用户完成一次判断后结束教学测试，不再继续出同类题。先用已确认的例子、通用规则和第一步动作小结，再询问她想自行套用，还是需要助手汇总剩余标签；不能替用户强行结束。
4. 用户需要继续时，先用树状代码块展示剩余标签整理后的完整层级，再把需要动手的项目按“移动 / 合并 / 存档 / 待确认”形成简洁建议，最后给实施顺序。不为每个原样保留的标签单独列表，不重新进入逐题问答。
5. 先确定一级标签，再改二级；不要边看边无限新增顶层标签。
6. 合并近义项时保留用户最自然、最容易记住的叫法。
7. 先归档过期标签，再处理活跃标签，界面会更快变清爽。
8. 整理完成后建议写一条“我的核心标签”置顶笔记，并在侧栏置顶最常用的标签，减少重复创建。
9. 所有迁移动作先形成候选清单并获得用户确认，再建议用户实际修改；不把尚未确认的试排结构当作最终结果。
10. 一个标签存在两种合理解释时，同时给出两个去向以及各自适用条件，让用户依据真实用法选择。
